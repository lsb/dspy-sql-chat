**SQL style guidelines**
- **Paper counting** – Because each row represents a paper‑author pair, always count papers with `COUNT(DISTINCT Title)`. Alias this count as `paper_count` unless the task explicitly asks for a different column name.
- **Grouping** – When grouping by multiple dimensions, list **all** grouping columns in the `GROUP BY` clause in the same order they appear in the `SELECT` list.
- **Ordering**  
  * Add an `ORDER BY` clause **only if** the natural‑language query explicitly requests ordering (e.g., “order by year descending”, “alphabetical list”, “top N”).  
  * For “top N” queries, order by the relevant metric **descending** and apply `LIMIT N`.  
  * If no ordering is mentioned, **do not** add any `ORDER BY`; the result order is irrelevant.
- **Distinct listings** – For requests like “list all papers …” or any query that could return duplicate rows because the table stores one row per author, use `SELECT DISTINCT` on the requested columns.  
  * Example: “List all papers from 2023 at ICLR” →  
    `SELECT DISTINCT Title FROM paper_authorships WHERE Conference = 'ICLR' AND Year = 2023`
- **Self‑joins / co‑author queries** – When joining the table to itself, ensure the result set does not contain duplicate rows. Use `SELECT DISTINCT` on the output columns and apply all filters before the join.
- **Average co‑author calculations** – For queries asking for “average co‑authors per paper” (or similar), compute the **average number of distinct authors per paper**. Use the pattern:

  ```sql
  WITH paper_counts AS (
      SELECT Title, COUNT(DISTINCT Author) AS author_count
      FROM paper_authorships
      GROUP BY Title
  )
  SELECT pa.Affiliation,
         AVG(pc.author_count) AS avg_coauthors_per_paper
  FROM paper_authorships pa
  JOIN paper_counts pc ON pa.Title = pc.Title
  GROUP BY pa.Affiliation
  ORDER BY avg_coauthors_per_paper DESC
  LIMIT <N>
  ```

- **Column order** – Preserve the column order expected by the task (e.g., `Affiliation, COUNT(DISTINCT Title) AS paper_count`).
- **NULL handling** – Do not filter out NULL values unless the query explicitly requests it.
- **Do not concatenate columns** to create a unique key; rely on `Title` alone.

**Edge cases**
- If the query asks for a count per group (e.g., per conference per year), return one row per group with `COUNT(DISTINCT Title)`.
- If the query asks for a list of values (e.g., all papers from ICLR), select exactly the requested columns, using `DISTINCT` when necessary, and **do not** add extra `ORDER BY` unless the request specifies ordering.
